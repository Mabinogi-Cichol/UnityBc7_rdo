# v0.5.1：修复部署后 DLL meta 解析错误

旧版 `tools/deploy_rgbm_portability.ps1` 为两个原生依赖写入 `.meta` 时，
PowerShell here-string 未包含文件末尾换行，Unity 启动后会报告：

```text
Unable to parse file Assets/Plugins/Bc7Rdo/bc7_rgbm_coordinator.dll.meta:
[Parser Failure at line 29: Expect ':' between key and value within mapping]
```

本版给新生成的 `.meta` 写入末尾换行，并在再次部署时修复已有文件的末尾换行，
保留 GUID 和平台导入设置。`bc7_rgbm_loader_gate.dll.meta` 同样修复。
补丁修改部署脚本和安装说明，编码逻辑沿用 v0.5.0。

## 已安装工程的修复

使用旧版部署脚本的工程，先关闭 Unity Editor 和 Worker，再使用当前仓库的
`tools/deploy_rgbm_portability.ps1` 重新部署；也可仅给上述两个 `.meta` 的最后一行
补换行并保存。已有损坏的 `.meta` 需要完成此修复，保留原 GUID 和设置。

发布 ZIP 不包含这两个 `.meta`，全新安装由 Unity 自动生成。两个下载包仍分别为：

1. **Editor Plugin**：将内容放入工程的 `Assets/Plugins/Bc7Rdo`，保留已有配置、
   asmdef、三个原生 DLL、`RgbmBindings~` 和许可目录。
2. **壳 DLL**：沿用 Unity 安装目录的替换／回滚方式，运行包内 `enable_unity_rdo.ps1`。

## 验证

在 Windows x64 Unity **2022.3.62f2** 的独立工程中，修复前复现两个文件相同的
第 29 行解析错误；补齐末尾换行后，解析错误为 **0**，batchmode 退出 **0**。
PluginImporter 检查通过：仅启用 Editor、CPU 为 x86_64、OS 为 Windows、非预加载，
两个文件的原 GUID 均保留。本次 Unity 复核范围为 meta 解析和平台导入设置。

两个 ZIP 提供完整递归 SHA256 校验；发布另附包校验及验证报告。
发布包不含 Oodle、Unity exe／PDB／原始 DLL、测试资源或运行缓存。
